# Commands

A standalone server accepts every command in this list. A cluster node accepts the commands marked **yes** in the Cluster column, plus `PING`, `AUTH`, `INFO`, `SLOWLOG`, and `DBSIZE`. Anything else returns `ERR unknown command ... or not supported in cluster mode`.

Command names are case-insensitive.

## Pub/sub, transactions, and server

These run on a standalone server.

| Command | Role |
|---------|------|
| `PUBLISH` | Send a message to a channel |
| `SUBSCRIBE` | Listen on one or more channels |
| `UNSUBSCRIBE` | Leave those channels |
| `MULTI` | Start a transaction |
| `EXEC` | Run it. A failed command rolls back the ones that already ran |
| `DISCARD` | Drop the queued commands |
| `WATCH` | Watch keys |
| `SELECT` | Choose a database |
| `FLUSHDB` | Delete the selected database |
| `FLUSHALL` | Delete every database |
| `SLAVEOF` | Replicate a master, or `NO ONE` to stop |
| `BGREWRITEAOF` | Rewrite the AOF file in the background |
| `REWRITEAOF` | Rewrite the AOF file |
| `SAVE` | Write `dbfilename` |
| `BGSAVE` | Write `dbfilename` in the background |
| `INFO` | Server, client, cluster, and keyspace sections |
| `DBSIZE` | Number of keys in the selected database |
| `SLOWLOG` | `GET`, `LEN`, and `RESET` |
| `AUTH` | Check `requirepass` |
| `PING` | `PONG`, or the argument echoed back |
| `COMMAND` | Command table |

`INFO`, `DBSIZE`, `SLOWLOG`, `AUTH`, and `PING` also run in cluster mode. In cluster mode `DBSIZE` reports database 0 on the node that received the command.
